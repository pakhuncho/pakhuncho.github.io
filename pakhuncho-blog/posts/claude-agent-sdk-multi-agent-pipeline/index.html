Claude Agent SDKでマルチエージェントパイプラインを構築する

# date: 2026-08-20 # read: 3 min # tags: [AI] [Claude]

複雑なタスクをひとつの巨大なプロンプトに詰め込むのではなく、役割の異なる複数のサブエージェントに分解して協調させる設計が、実運用では扱いやすい。ここでは Claude Agent SDK を使い、調査・実装・検証を担当する3つのエージェントを orchestrator が束ねる最小構成を組んでみる。

なぜマルチエージェントにするのか

単一のプロンプトで「調査して、実装して、レビューする」まで一気にやらせようとすると、プロンプトはどんどん肥大化し、途中の思考過程がログとして追いにくくなる。役割ごとにエージェントを分けると、

  • 各エージェントの system prompt を短く保てる
  • 途中経過(調査結果・実装コード・レビュー結果)がそれぞれ独立したログとして残る
  • 役割単位でモデルやパラメータ(温度、max_tokens など)を変えられる

というメリットがある。デメリットは呼び出し回数が増えることと、エージェント間の情報の受け渡し設計が必要になることだ。

最小構成

今回は researcher・implementer・reviewer の3エージェントを、orchestrator が直列に呼び出すだけのシンプルな構成にした。

python
from anthropic import Anthropic

client = Anthropic()

def run_agent(role: str, task: str) -> str:
    # role ごとに system prompt を切り替える
    response = client.messages.create(
        model="claude-sonnet-5",
        max_tokens=1024,
        system=SYSTEM_PROMPTS[role],
        messages=[{"role": "user", "content": task}],
    )
    return response.content[0].text

def orchestrate(task: str) -> str:
    plan = run_agent("researcher", task)
    code = run_agent("implementer", plan)
    return run_agent("reviewer", code)

SYSTEM_PROMPTS には role ごとの system prompt を辞書で持たせている。researcher は「実装方針を箇条書きでまとめる」、implementer は「researcher の方針をもとにコードを書く」、reviewer は「実装コードの問題点を指摘する」という役割に絞ることで、それぞれの system prompt を数行に収められた。

orchestrator と3つのサブエージェントの関係

orchestrator は各エージェントの出力をそのまま次段に渡すだけの単純な実装だが、役割を分離したことでプロンプトが短くなり、途中経過をログとして人間が読みやすくなる利点がある。

次にやること

現状は researcher → implementer → reviewer の一方向パイプラインで、reviewer が問題を指摘しても implementer に差し戻す仕組みがない。次回はここに検証エージェントの自己修正ループ(reviewer の指摘を implementer に戻して再実装させる)を足していく。あわせて、各エージェントの呼び出しコストをログに残し、役割ごとにどのモデルを使うのが費用対効果として妥当かも検証したい。
