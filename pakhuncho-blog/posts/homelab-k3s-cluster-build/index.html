自宅Kubernetesクラスタでホームラボを構築した話

# date: 2026-08-12 # read: 2 min # tags: [インフラ] [k8s]

クラウドの検証環境は便利だが、常時起動しておくとそれなりの費用になる。個人開発で試すサービス(CI、ちょっとしたAPI、監視スタックなど)を自宅で完結させたくなり、ミニPC3台で k3s クラスタを組んだ。

構成

  • ミニPC × 3台(それぞれ8コア/32GB RAM)
  • control-plane 1台 + worker 2台
  • OS は Ubuntu Server、コンテナランタイムは containerd
  • ロードバランサ代わりに MetalLB を使用

k3s を選んだ理由は単純で、フル機能の kubeadm クラスタに比べてセットアップが軽く、ミニPC程度のリソースでも余裕を持って動くため。

セットアップの流れ

control-plane 側で k3s をインストールし、発行されたトークンを worker 側に渡すだけで join できる。

bash
# control-plane
curl -sfL https://get.k3s.io | sh -

# トークン確認
sudo cat /var/lib/rancher/k3s/server/node-token

# worker 側
curl -sfL https://get.k3s.io | K3S_URL=https://<control-plane-ip>:6443 \
  K3S_TOKEN=<node-token> sh -

worker が2台とも join できたら kubectl get nodes で Ready になっているか確認する。ここまでは特につまずくところはなかった。

つまずいたところ

  • ミニPCの無線LANだけで組んだところ、Pod 間通信が不安定になった。有線LANに切り替えて解消。
  • MetalLB のアドレスプールをホームルーターのDHCP範囲と被らせてしまい、IPが衝突。プール範囲を明示的に分離して解決。
  • ストレージは最初 hostPath で済ませていたが、ノード障害時にデータが追えなくなるため Longhorn に切り替えた。

セルフホストしているもの

現状は個人用の CI ランナー、簡単な API サーバー、Grafana + Prometheus の監視スタックをこのクラスタ上で動かしている。電気代は増えたが、検証環境をいつでも壊して作り直せる気軽さは、クラウドの従量課金よりも精神的なコストが低い。
