RAGのチャンク戦略を4パターン比較する

# date: 2026-07-24 # read: 2 min # tags: [AI] [RAG]

RAG の精度は検索対象のドキュメントをどう分割するかにかなり左右される。同じ埋め込みモデル・同じ検索件数でも、チャンク戦略を変えるだけで回答精度が変わることがあるので、代表的な4手法を同じデータセットで比較してみた。

比較した4手法

  1. 固定長チャンク — 文字数(または token 数)で機械的に分割する。実装が最も簡単。
  2. 意味単位チャンク — 段落や見出しなど、文書の論理構造に沿って分割する。
  3. 階層型チャンク — 見出し単位の大きいチャンクと、その中の段落単位の小さいチャンクを両方保持し、検索時に使い分ける。
  4. スライディングウィンドウ — 固定長チャンクに一定の重なり(オーバーラップ)を持たせ、文脈の切れ目でチャンク境界が情報を分断しにくくする。
python
def sliding_window_chunks(text: str, size: int = 500, overlap: int = 100):
    chunks = []
    start = 0
    while start < len(text):
        end = start + size
        chunks.append(text[start:end])
        start += size - overlap
    return chunks

結果の傾向

社内ドキュメント(FAQ・仕様書混在)を対象に、同じ質問セットで回答精度を比較したところ、大まかに次のような傾向が見えた。

  • 固定長は実装が簡単な反面、文の途中でチャンクが切れて文脈を失うケースが目立った
  • 意味単位は文脈の分断は少ないが、見出しの粒度が文書ごとにバラバラだとチャンクサイズの分散が大きくなり、検索スコアが不安定になった
  • 階層型は精度は良いが、インデックス構築・検索ロジックの実装コストが最も高い
  • スライディングウィンドウは固定長より文脈の分断が少なく、実装コストと精度のバランスが良かった

選んだ戦略

今回のデータセットでは、実装コストと精度のバランスからスライディングウィンドウを採用することにした。ただし文書の種類(FAQのように短い単位で完結する文書と、仕様書のように長い文脈が必要な文書)によって最適な戦略は変わるはずなので、次は文書タイプごとにチャンク戦略を切り替えるハイブリッド構成を試してみたい。
